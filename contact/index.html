Guidelines for Submitting Technical Bug Reports

To help our engineering team reproduce and resolve edge cases swiftly, please include the following details in your message:

  • Tool Name & URL: The exact utility page where the issue occurred (e.g., /json-to-csv/ or /jwt-decoder/).
  • Browser & Operating System: Your browser version (Chrome, Firefox, Safari, Edge) and OS (Windows, macOS, Linux, iOS, Android).
  • Sample Input (Sanitized): A sanitized, non-confidential snippet of input data that triggered the parsing anomaly.
  • Expected vs. Actual Output: What output you expected according to standard specifications vs. what was rendered.

Frequently Asked Contact & Support Questions

Q: Can I request a new developer tool or converter?

Yes, absolutely! We love community input. Send an email to support@omnitechtools.com with the subject line "[Tool Request]" describing the utility, typical input/output formats, and common use cases.

Q: Do you offer commercial API access for automated backend conversions?

OmniTools is built as a client-side web application running locally in user browsers. However, for enterprise teams requiring offline CLI or batch script automation, reach out to support@omnitechtools.com for integration guidance.

Q: How do you handle security vulnerability disclosures?

We take responsible security disclosures seriously. If you identify a potential security vulnerability, Cross-Site Scripting (XSS) risk, or dependency issue, please email security@omnitechtools.com with proof-of-concept steps. We aim to acknowledge reports within 12 hours.

Q: Can our educational institution or coding bootcamp link to OmniTools?

Yes. OmniTools is completely free and public. Universities, high schools, coding academies, and open-source documentation projects are welcomed to reference and link to our tools and technical guides.
